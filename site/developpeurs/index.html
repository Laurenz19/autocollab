Documentation développeurs

Pilotez AutoCollab depuis vos outils : un assistant IA compatible MCP (claude.ai, ChatGPT, Claude Code, Claude Desktop, Cursor, VS Code…), un scénario n8n ou un script. Ce tutoriel vous mène de l'adresse du serveur à un premier agent lancé depuis votre assistant.

Le principe

MCP (Model Context Protocol) est le standard ouvert qui permet à un assistant IA d'utiliser des outils externes. AutoCollab expose un serveur MCP : une fois connecté, votre assistant peut, en votre nom et avec vos droits :

  • lister, créer et modifier vos agents et vos chaînes ;
  • les lancer, ou lancer une tâche ponctuelle, puis suivre l'exécution jusqu'au résultat ;
  • lire et compléter votre contexte (règles, glossaire, notes par site) ;
  • répondre à une validation en attente, uniquement sur votre décision explicite.

Il ne peut rien supprimer. Chaque agent ou chaîne créé par MCP porte un badge « MCP » dans l'application.

1. Préparer la connexion

L'adresse du serveur MCP est celle de votre instance AutoCollab suivie de /mcp. Saisissez-la ci-dessous : tous les exemples de cette page se mettent à jour. Rien n'est envoyé, tout reste dans votre navigateur.

Adresse MCP : https://<votre-serveur>/mcp

Encore plus simpleDans l'application, la page Développeurs › MCP affiche ces mêmes configurations, déjà remplies avec l'adresse de votre serveur et votre clé.
claude.ai et ChatGPT exigent une adresse publique en httpsLeurs serveurs appellent AutoCollab depuis Internet : une adresse locale (localhost, 192.168…) ne fonctionne pas. L'administrateur du serveur renseigne cette adresse dans PUBLIC_URL (fichier .env) puis redémarre l'application. Claude Code, Cursor, VS Code et Claude Desktop tournent sur votre poste : une adresse du réseau local leur suffit.

2. OAuth ou clé d'API ?

MéthodePourComment
OAuth recommandéclaude.ai, ChatGPT, et tout client qui gère OAuthVous collez l'adresse, l'outil vous envoie sur la page « Autoriser » d'AutoCollab, vous cliquez. Aucune clé à manipuler, accès révocable à tout moment.

3. Créer une clé d'API

Inutile pour claude.ai et ChatGPT : passez directement à l'étape 4.

  1. Connectez-vous à AutoCollab et ouvrez Développeurs (en bas du menu de gauche).
  2. Onglet Démarrage, rubrique 1. Créer une clé d'API : donnez-lui un nom parlant (« Claude Code – portable », « n8n production »…) puis cliquez sur Créer.
  3. Copiez la clé tout de suite : elle commence par ac_ et ne sera plus jamais affichée. Seule son empreinte est conservée.

Une clé par outil, dix au plus par compte : vous pourrez ainsi en révoquer une sans couper les autres. La colonne « Dernière utilisation » montre lesquelles servent encore.

Une clé vaut votre mot de passeElle agit avec vos droits sur vos agents et vos connexions. Ne la mettez jamais dans un dépôt Git ni dans un message ; révoquez-la au moindre doute.

4. Connecter votre outil

Choisissez votre outil :

claude.ai OAuth

  1. Ouvrez Paramètres › Connecteurs puis Ajouter un connecteur personnalisé.
  2. Nom : AutoCollab. URL : https://<votre-serveur>/mcp. Validez.
  3. Cliquez sur Se connecter. Vous arrivez sur la page « Autoriser » d'AutoCollab (connectez-vous d'abord si besoin) : vérifiez le nom de l'application et cliquez sur Autoriser.
  4. Dans une nouvelle conversation, activez le connecteur AutoCollab depuis le menu des outils.

Avec Claude Team ou Enterprise, un propriétaire de l'organisation ajoute d'abord le connecteur pour tout le monde ; chacun clique ensuite sur « Se connecter » pour autoriser son propre compte.

ChatGPT OAuth

  1. Ouvrez Paramètres › Applications et connecteurs › Paramètres avancés et activez le Mode développeur.
  2. Cliquez sur Créer. Nom : AutoCollab ; URL du serveur MCP : https://<votre-serveur>/mcp ; authentification : OAuth.
  3. ChatGPT vous envoie sur la page « Autoriser » d'AutoCollab : cliquez sur Autoriser.
  4. Dans une conversation, choisissez AutoCollab dans la liste des connecteurs.

5. Vérifier la connexion

      
Ouvrez une nouvelle conversation et essayez, dans l'ordre :

      
    
        
  1. « Quels sont mes agents AutoCollab ? » : l'assistant appelle list_agents. S'il vous les liste, la connexion fonctionne.
    2. 
        
  2. « Lance une tâche AutoCollab : va sur service-public.fr et trouve la date limite de la CA12. » : il appelle run_task, puis suit l'exécution avec get_run jusqu'au résultat. Vous la voyez aussi en direct dans la page Exécutions.
    3. 
        
  3. « Rédige-moi un agent qui télécharge chaque mois le relevé Qonto du mois précédent. Montre-le-moi avant de le créer. » : il prépare la consigne, vous la relisez, puis il la crée avec create_agent.
    4. 
      

      
La bonne méthode pour une nouvelle tâcheFaites rédiger, testez une fois comme tâche ponctuelle limitée aux sites nécessaires, vérifiez le résultat dans l'application, et seulement ensuite enregistrez un agent et planifiez-le. Gardez le mode avec validation tant que la tâche envoie, supprime ou paie quelque chose.

Sécurité

      
    
        
  • Vos droits, pas plus. L'assistant ne voit que vos agents, vos exécutions et votre contexte, jamais ceux de vos collègues. Il n'accède à l'administration que si vous êtes administrateur.
    • 
        
  • Aucune suppression. Ni agent, ni chaîne, ni exécution ne peut être supprimé par MCP ; le contexte se modifie par ajouts et remplacements ciblés.
    • 
        
  • Les validations restent humaines. AutoCollab demande à l'assistant de n'appeler answer_approval qu'avec votre réponse explicite. Gardez le mode avec validation pour les actions difficiles à annuler.
    • 
        
  • Révocation immédiate. Développeurs › MCP › Applications autorisées liste les assistants connectés par OAuth : « Révoquer » coupe l'accès. Les clés se révoquent dans Développeurs › Démarrage.
    • 
        
  • Double authentification. Si votre organisation l'impose, activez-la d'abord : les clés et autorisations sont refusées tant qu'elle ne l'est pas.
    • 
      

    


    

      
Dépannage

      
claude.ai ou ChatGPT n'arrive pas à se connecter
L'adresse doit être publique et en https, et identique à PUBLIC_URL dans le .env du serveur. Ouvrez https://<votre-serveur>/.well-known/oauth-protected-resource dans votre navigateur : vous devez voir un JSON dont resource se termine par /mcp. Sinon, corrigez PUBLIC_URL et redémarrez.

      
Erreur 401 Unauthorized
La clé est absente, mal copiée, révoquée, ou l'en-tête est mal formé. Il doit être exactement Authorization: Bearer ac_… (un espace après « Bearer »). Créez une nouvelle clé au besoin.

      
Erreur 403 Forbidden
Trois causes : votre compte a un mot de passe provisoire à changer, ou doit activer la double authentification (connectez-vous à l'application pour le faire) ; ou la requête vient d'une page web d'un autre site (en-tête Origin différent), ce qui est refusé par sécurité.

      
Claude Desktop n'affiche pas AutoCollab
Vérifiez que Node.js est installé (npx --version dans un terminal), que le JSON est valide (pas de virgule en trop), puis quittez vraiment l'application avant de la rouvrir. Les journaux sont dans le dossier logs à côté du fichier de configuration (mcp-server-autocollab.log).

      
L'assistant ne voit pas un outil récent
Il garde la liste reçue à la connexion. Reconnectez le connecteur (ou redémarrez le client) et ouvrez une nouvelle conversation.

      
Une tâche lancée reste « En attente »
Vos exécutions passent une par une : une autre est en cours, attend une validation, ou la page Mes connexions est ouverte. Demandez à l'assistant list_runs pour voir la file.

      
Erreur 429 Too Many Requests
Plus de 300 appels par minute depuis la même adresse IP : ralentissez la boucle de suivi (un get_run toutes les quelques secondes suffit).

OAuth 2.1

      
Tout est découvert automatiquement à partir du 401 ; ces routes ne servent qu'à écrire votre propre client.

      

      

        
RouteRôle

        
          
GET /.well-known/oauth-protected-resourceMétadonnées de la ressource (RFC 9728)

          
GET /.well-known/oauth-authorization-serverMétadonnées du serveur d'autorisation (RFC 8414)

          
POST /oauth/registerEnregistrement dynamique du client (RFC 7591)

          
GET /oauth/authorizePage « Autoriser » ; response_type=code, PKCE S256 obligatoire

          
POST /oauth/tokenauthorization_code ou refresh_token

          
POST /oauth/revokeRévocation (RFC 7009)

        
      

      

      
Jeton d'accès aco_… valable 1 h, uniquement sur /mcp ; jeton de renouvellement acr_… valable 30 jours, remplacé à chaque usage.


      
Échange type

      

      
Une erreur métier (exécution introuvable, aucune validation en attente…) revient comme un résultat avec isError: true ; un outil inconnu ou des arguments invalides, comme une erreur JSON-RPC -32602. Les notifications reçoivent 202 sans corps ; les lots sont acceptés.


      
Documentation lisible par les IA

      
https://<votre-serveur>/llms.txt (résumé) et /llms-full.txt (tout) sont publics, au format llms.txt, et générés à partir du code : ils sont toujours à jour. Donnez-les à un assistant qui n'est pas connecté par MCP pour qu'il vous aide à écrire un script.
